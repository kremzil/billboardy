# Данные и импорт

Этот документ описывает рабочие входные данные и связанные с ними файлы в репозитории.

## Основные типы источников

В репозитории сейчас встречаются несколько видов исходных данных:

- WooCommerce export
- KMZ-derived CSV
- XLSX файлы с дополнительными точками
- CSV, полученные конвертацией из XLSX

## Файлы в корне репозитория

### WooCommerce reference

- `wc-adsPlaces.csv`

Используется как reference/export файл. Это не основной frontend runtime asset.

### KMZ

- `Interaktívna mapa reklamných plôch.kmz`
- `kmz-relevant-adspaces.csv`

KMZ — исходный файл. CSV рядом — уже подготовленный flat export, с которым удобнее работать для импорта и анализа.

### Knosic XLSX и CSV

- `knosic_blb.xlsx`
- `knosic_clv.xlsx`
- `knosic_blb.csv`
- `knosic_clv.csv`

XLSX — исходные таблицы.
CSV — рабочие производные файлы для импорта/сравнения.

## Как это связано с runtime

Эти файлы сами по себе не обслуживают карту напрямую.

Обычный поток такой:

1. исходный файл подготавливается;
2. импортируется через админку WordPress;
3. данные попадают в собственную таблицу;
4. REST API читает уже нормализованные данные из таблицы;
5. frontend работает только через API.

## Нормализованные типы носителей

Для runtime API используются стабильные значения `media_type`:

- `billboard` — Billboard
- `bigboard` — Bigboard
- `citylight` — Citylight
- `bridge` — Most
- `banner` — Plachta
- `facade` — Fasáda
- `mega` — Mega plocha

Словацкие названия остаются UI-labels. Старые alias-значения вроде `most`, `plachta`, `fasada` и `mega-plocha` должны читаться как совместимые входные значения, но новые импорты должны писать canonical значения из списка выше.

## Что важно помнить

- Корневые CSV/XLSX/KMZ — это source/reference data, а не production API.
- После смены источника данных нужно заново импортировать данные, а не ждать, что frontend увидит файл сам.
- После крупного обновления данных имеет смысл:
  - очистить cache в админке плагина;
  - прогреть cache типовых вьюпортов.

## Когда смотреть этот документ

Открывайте этот файл, если нужно понять:

- откуда пришли текущие точки;
- какие файлы считаются исходными;
- какой путь проходит data до появления на карте.
